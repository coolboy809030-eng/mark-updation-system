5. EVERY GOOGLE APPS SCRIPT FUNCTION / API ENDPOINT
--------------------------------------------------------------------------------
The Google Apps Script backend template resides in:
/src/components/result/GoogleSheetStructureModal.tsx (Lines 26 to 234).

Endpoints and Request Handlers:
1. doGet(e):
   - Handles incoming HTTP GET requests.
   - Action Dispatcher:
     * ?action=getStudents&class=Class_5: Calls handleGetStudents(e, ss). Fetches student roster (Roll, Adm No, Name, Father Name, Mother Name, DOB, Opted Subject).
     * ?action=fetchClassExamData&class=Class_5: Calls handleFetchClassExamData(e, ss). Reads all student rows along with all test marks columns (PT-1, PT-2, HY, PT-3, PT-4, AE, Attendance).
     * ?action=ping: Returns JSON { status: "success", message: "Google Apps Script backend connected!", timestamp: ... }.
     * Default / Fallback: Returns student roster if 'class' parameter is provided.
   - Response Format: ContentService.MimeType.JSON with headers for CORS.

2. doPost(e):
   - Handles incoming HTTP POST requests.
   - Action Dispatcher: Calls handlePostData(e, ss).
   - Expected Payload: JSON.stringify({ records: [ SheetSubmissionRecord, ... ] }) or individual payload.
   - Logic:
     * Iterates over each submission record.
     * Identifies sheet named "Class_" + normalizeClassName(record.class).
     * Locates the student row by Roll number or Admission Number.
     * Maps subject + segment/type to the exact column header (e.g. "English PT-1", "Mathematics HY-WRT", "Attendance HY").
     * Writes cell value into the Google Sheet.
     * Appends an audit log row into the "Sync_Logs" sheet with timestamp, teacher/client IP, and record details.
   - Response: JSON { status: "success", updatedCount: N, message: "Records successfully updated in Sheet" }.

3. Internal Helper Functions inside Code.gs:
   - handleGetStudents(e, ss): Scans demographic columns and returns JSON array of students.
   - handleFetchClassExamData(e, ss): Reads demographic + dynamic test columns into rawMarks dictionary.
   - handlePostData(e, ss): Batch updates cell values and writes to Sync_Logs.
   - getOrCreateSheet(ss, sheetName): Returns existing sheet or initializes sheet with headers.
   - normalizeClassName(c): Strips prefixes and standardizes class sheet tab names (e.g. "Class 5" -> "Class_5").

6. EVERY GOOGLE SHEET-RELATED FUNCTION & SCHEMA
--------------------------------------------------------------------------------
Schema Architecture:
Each class has a dedicated sheet tab in the Google Spreadsheet (e.g. "Class_1", "Class_2", ... "Class_10", "Class_Nursery", "Class_LKG", "Class_UKG").

Standard Column Schema:
- Col 1 (A): Roll No (Numeric index, e.g. 1, 2, 3...)
- Col 2 (B): Admission No (e.g. "PIS-2025-0101")
- Col 3 (C): Student Name (Full Name string)
- Col 4 (D): Father's Name
- Col 5 (E): Mother's Name
- Col 6 (F): Date of Birth (YYYY-MM-DD or DD/MM/YYYY)
- Col 7 (G): Gender (M / F)
- Col 8 (H): Opted Subject / 2nd Language ("Urdu" | "Sanskrit" | "None")
- Col 9 (I): Phone / Contact Number
- Col 10+ (J..): Subject Marks Columns following naming pattern:
  * "{Subject} PT-1" (Max 20)
  * "{Subject} PT-2" (Max 20)
  * "{Subject} HY" or "{Subject} HY-WRT" (Max 80)
  * "{Subject} PT-3" (Max 20)
  * "{Subject} PT-4" (Max 20)
  * "{Subject} AE" or "{Subject} AE-WRT" (Max 80)
  * "Attendance HY" (Term-1 Present Days)
  * "Attendance AN" or "Attendance AE" (Term-2 Present Days)

Supporting Sheets:
- "Sync_Logs": Timestamp, User/Action, Class, Subject, Records Count, Status.
- "Config": Portal settings, session year ("2025-2026"), working days parameters.

15. EVERY RESULT GENERATION MODULE & CALCULATION ENGINE
--------------------------------------------------------------------------------
Primary Files:
- /src/components/result/ResultGeneratorApp.tsx
- /src/utils/resultCalculator.ts

Calculation Formulas:
1. Single Term Subject Evaluation (HY or AE):
   - Periodic Component (10 Marks): Best score between (PT-1, PT-2) for Term-1 or (PT-3, PT-4) for Term-2, scaled to 10 marks (BestPT / 2).
   - Portfolio (PF): 5 Marks (Derived/Awarded).
   - Subject Enrichment (SE): 5 Marks (Derived/Awarded).
   - Written Examination (WRT): 80 Marks.
   - Total Subject Score = (BestPT / 2) + PF (5) + SE (5) + Written (80) = 100 Marks Max.

2. Dual Term Aggregation (BOTH):
   - Grand Total = (Term-1 Subject Total + Term-2 Subject Total) / 2.
   - Grand Percentage = (Total Obtained across all subjects / Total Max Marks) * 100.

3. Grading Scale:
   - 91% - 100%: Grade A1 (Grade Point 10.0)
   - 81% - 90%: Grade A2 (Grade Point 9.0)
   - 71% - 80%: Grade B1 (Grade Point 8.0)
   - 61% - 70%: Grade B2 (Grade Point 7.0)
   - 51% - 60%: Grade C1 (Grade Point 6.0)
   - 41% - 50%: Grade C2 (Grade Point 5.0)
   - 33% - 40%: Grade D  (Grade Point 4.0)
   - 0%  - 32%: Grade E  (Essential Repeat / Fail, Grade Point 0.0)

4. Ranking Algorithm (rankClassStudents):
   - Sorts students strictly by Total Marks Obtained descending.
   - Resolves ties using Percentage descending, then Roll number ascending.
   - Assigns 1-based ranks (#1, #2, #3...).

26. KNOWN ARCHITECTURAL BOTTLENECKS, COUPLING & RISKS
--------------------------------------------------------------------------------
1. State Monoliths:
   - App.tsx (957 lines) and ResultGeneratorApp.tsx (1190 lines) hold excessive state variables (modals, allotments, configs, filter selections).
   - Recommendation for Academic Hero: Decompose into modular React Contexts or Zustand stores (e.g. useAuthStore, useExamStore, useSystemConfigStore).

2. Dual Data Source of Truth & Race Conditions:
   - Master exam records exist concurrently in localStorage ('pis_master_exam_store_v2') and in remote Google Sheets.
   - If multiple teachers edit the same sheet simultaneously, local storage may become out of sync with Google Sheets unless a fresh pull is forced.

3. Google Apps Script Quotas & Latency:
   - Google Apps Script has execution quotas (6 mins max execution time, concurrent request limits).
   - Rapid sequential doPost requests can trigger 429 Too Many Requests or CORS redirect failures if not batched.

4. Client-Side PDF Generation Memory Footprint:
   - html2canvas-pro at scale 2 rasterizes full DOM trees to canvas in browser memory.
   - Generating 100+ report cards simultaneously in BulkReportCards can cause high memory usage on low-spec client machines.

5. Authentication Security Limitations:
   - Master PIN ('1234') is stored in plain text in localStorage ('pis_admin_pin_v2').
   - No cryptographic salt/hash or JWT token is utilized. Suitable for internal school local networks, but requires secure hashing for multi-tenant production.

6. Absence of True Relational Integrity:
   - Roster data relies on Google Sheet cell matching by Roll or Adm No string.
   - Changing a student's Roll number midway through the session without updating existing records can lead to orphaned entries.
